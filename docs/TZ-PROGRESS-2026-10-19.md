Пункт 1: source/live и source/day, а также быстрая сводка содержат SOL, покупки/продажи, top10 в процентах, проверку прав и изображение. Данные только из наблюдений с at не позже публикации. Неизвестное остаётся null/«—». SOL кривой не подменяет SOL нового пула после миграции.

Дата создания берётся из подтверждённого create-log или из успешной транзакции инициализации mint. Один ограниченный запрос истории; переполненная страница не выдаётся за начало истории. Проверка транзакции после бюджетной отсрочки продолжается без повторного поиска. Если доказательств нет, возраст неизвестен; время миграции не используется как рождение.

Изображения берутся из имеющихся данных или metadata URI разрешённых публичных gateway. Загрузка ограничена по размеру/времени, без переходов по redirects и обращений к внутренним адресам. Необязательные метаданные больше не уничтожают уже полученную проверку прав mint при отсрочке RPC.

До выкладки: исходный production жив, но state.json около 47,4 МБ превышает унаследованный порог 45 МБ. Порог не повышался. Нужно исправить хранение с сохранением наблюдений. Рабочая цель Helius в новой версии снижена до 17/мин; DBC/LaunchLab не выключаются.

Playwright-файл перенесён из *.cjs в mobile.spec.js, чтобы обязательная Node-команда не пыталась запускать тест другого framework. Реальные мобильные проверки сохранены отдельным workflow.

Пункт 2: passMode хранится отдельно для before/after. Все включённые модули выбранных уровней обязаны пройти. Каждый получает свой cutoff acceptedAt + verdictMinutes; общий срок — максимум, включая уровень 2 (уточнение владельца). Сигнал публикуется после срока; задержка обработки ограничена двумя минутами, старые допуски не превращаются в свежие сигналы. Журнал schema=2 сохраняет отдельные вердикты, признаки и времена. Старый журнал читается без изменения; collector переводит загруженную конфигурацию на новый режим, сохраняя её пороги.

Составные conds[] сохраняются в конфигурации и при добавлении результата исследования в Окно. Суточные сигналы берутся из серверного счётчика по UTC+5. Переключение режима существующей кнопкой отправляется в control-api; локальное окно показа остаётся настройкой телефона. UI и стили сохранены.

Пункт 3: настройки и цели И1 раздельны по фазам; цели не меняют эпоху, включая перевод прежнего общего конфига в два одинаковых. Ранние признаки ограничены decisionAt от acceptedAt. Подбор использует мелкую сетку порогов и 1–3 условия, временной holdout, отсекает близкие дубли; усложнение допускается только при улучшении отсечения отрицательных минимум на 5 п.п. без потери положительных. Надёжные признаки: права/тип токена, наблюдённый спрос и сделки, SOL и концентрация; метаданные — только с временем получения. Идентификация ботов, снайперов и история создателя остаются неизвестными.

Авто-модули сохраняются сервером с id, фазой, сроком, датой рождения, первичными train/holdout и отдельным live по будущим допускам. Подбор — не чаще часа. Придуманный демонстрационный модуль больше не выдаётся за результат. Телефон использует существующие формы, отправляет цели и фазовые настройки в control-api. Мобильный сценарий исправлен также под актуальный текст пустого графика; повторная проверка после пуша.

Пункт 4: И2 получает только серверные «Прошли», настройки и цели разделены по фазам. Признаки фиксируются через 1–15 минут от acceptedAt, как в Окне. Обновлённый пункт 4 получен git pull из main; прежний отсчёт после «Прошли» исправлен до выкладки. Подбор разделён по id и версии родительского модуля И1, не сохраняет равные/более слабые унаследованные условия. Индивидуальные кривые 0–300 с шагом 5 минут передаются в polygon-2 и подключены к существующему графику.

Реальные доступные признаки И2: изменения цены, отклонение от наблюдённого пика/просадка, ускорение подтверждённых пятиминутных окон, рост SOL, изменение концентрации при двух снимках, известный возраст и час. Остальные ключи явно null: нет достоверной идентификации кошельков/повторных покупок и минутных продаж из пятиминутных агрегатов. Будущие свечи, загруженные позже вердикта, не попадают в ранние признаки.

Пункт 5: восемь отдельных дисковых банков с целями 50–5000. Новейшие допуски вытесняют старые независимо по фазе/классу, повторы и ранее вытесненные старые записи не создают повторных выгрузок. Кривые сжимаются без потерь, при публикации разворачиваются по одной монете. Автоподбор получает размеченные записи из банков. Сервер увеличивает минимальную ёмкость до целей исследований, в том числе при изменении этих целей. Существующая шестерёнка хранилища отправляет настройки через /api/research-storage; счётчики берутся с сервера. Старые файлы и наблюдения не удалялись.

Пункт 6: /api/modules с generation-CAS и проверкой evalSig принимает создание/редактирование/удаление. Имя не меняет семантическую подпись, оценки или активацию Окна; изменение условий/времени сбрасывает train/holdout/live/test и liveFrom. Удаление хранит tombstone, исключает модуль из библиотеки, исследований и конфигурации Окна. Собственные модули используют те же серверные поля и формы. Телефон больше не считает localStorage.r1mods источником модулей.

/api/module-test проверяет выбранные модули на выбранных фазе/классах из серверных банков, хранит ранги, числа пропущенных, неизвестных и время. Для новых размеченных монет сохраняются сжатые ранние срезы по минутам: тест изменённого срока и тихий прогон не используют более поздние признаки. Если нужного старого среза нет, результат неизвестен. Тихие оценки считаются порциями раз в час, только для acceptedAt >= liveFrom.
